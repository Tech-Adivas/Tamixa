## Document Formats

### User Guides
- **Format**: Step-by-step instructions with screenshots descriptions
- **Audience**: Non-technical users
- **Length**: 5,000-10,000 words
- **Style**: Conversational, clear, actionable

### Technical Documentation
- **Format**: Architecture diagrams, code samples, API specs
- **Audience**: Developers, architects
- **Length**: 10,000-15,000 words
- **Style**: Technical, precise, comprehensive

### Feature Highlights
- **Format**: Benefits-focused with examples
- **Audience**: All users, stakeholders
- **Length**: 5,000-7,000 words
- **Style**: Engaging, visual, benefit-driven

### Quick Start Guides
- **Format**: Checklists, quick tasks, shortcuts
- **Audience**: All users
- **Length**: 2,000-3,000 words
- **Style**: Concise, actionable, scannable

## Contributing to Documentation

### For Documentation Updates

**Process**:
1. Identify outdated or missing content
2. Create issue in GitHub
3. Submit pull request with changes
4. Request review from documentation team
5. Merge after approval

**Guidelines**:
- Use clear, simple language
- Include examples and screenshots
- Test all instructions
- Update version history
- Cross-reference related docs

**Style Guide**:
- Use active voice
- Write in second person ("you")
- Use present tense
- Keep sentences short
- Use bullet points for lists
- Include code examples where relevant

### For New Documentation

**Proposal**:
1. Identify documentation gap
2. Create proposal with outline
3. Get approval from product/engineering
4. Write draft
5. Review and iterate
6. Publish

**Templates**:
- User Guide Template (coming soon)
- Technical Doc Template (coming soon)
- Feature Highlight Template (coming soon)
